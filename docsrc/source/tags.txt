Tag Reference
=============

Default fields
--------------

The following fields are common to almost all music files.

.. describe:: __accessed

    The date and time the file was last accessed, in YYYY-MM-DD HH:MM:SS format.

.. describe:: __app

    The application name: puddletag v0.10.4 depending on version number.

.. describe:: __bitrate

    The bitrate of the file in kb/s. Note that it's a string with kb/s appended as in '213 kb/s' and not '213'.

.. describe:: __bitrate_num

    The bitrate of the file in whole kb/s, as a number: 213 for '213 kb/s'.

.. describe:: __channels

    The number of audio channels: 1 for mono, 2 for stereo.

.. describe:: __created

    The creation date of the file in YYYY-MM-DD HH:MM:SS format.

.. describe:: __dirpath

    The path of the directory the file resides in. /media/Multimedia/Music/myfile.mp3 has __dirpath /media/Multimedia/Music

.. describe:: __dirname

    The name of the directory the file resides in. /media/Multimedia/Music/myfile.mp3 has __dirname Music

.. describe:: __ext

    Extension of the file. /media/Multimedia/Music/myfile.mp3 has extension mp3

.. describe:: __file_access_date

    The date the file was accessed in YYYY-MM-DD format

.. describe:: __file_access_datetime

    The date including the time the file was accessed in YYYY-MM-DD HH:MM:SS format

.. describe:: __file_access_datetime_raw

    UNIX time of the file's last access eg. 1234567890.

.. describe:: __file_create_date

    Creation date of the file in YYYY-MM-DD format.

.. describe:: __file_create_datetime

    File's creation date in YYYY-MM-DD HH:MM:SS format.

.. describe:: __file_create_datetime_raw

    UNIX time of file creation date eg. 1234567890.

.. describe:: __file_mod_date

    Date the file was last modified in YYYY-MM-DD format.

.. describe:: __file_mod_datetime

    Time the file was last modified in YYYY-MM-DD HH:MM:SS format.

.. describe:: __file_mod_datetime_raw

    UNIX time of file's last modification date.

.. describe:: __file_size

    The file's size in human-readable format.

.. describe:: __file_size_bytes

    The file's size in bytes.

.. describe:: __file_size_kb

    The file's size in KB.

.. describe:: __file_size_mb

    The file's size in MB (to two decimal places).

.. describe:: __filename

    The filename of the file with the folder stripped. e.g. the __filename of  /media/Multimedia/Music/myfile.mp3 is myfile.mp3

.. describe:: __filename_no_ext

    The file's filename without extension.

.. describe:: __filetype

    The format of the file. Currently the info is very sparse.

.. describe:: __frequency

    The sample rate of the file in kHz. Note that it's a string with kHz appended as in '44.1 kHz' and not '44.1'

.. describe:: __frequency_num

    The sample rate of the file in kHz, as a number: 44.1 for '44.1 kHz'.

.. describe:: __image

    Refers to the album art present in the file.

.. describe:: __image_mimetype

    MimeType of the first cover image in the file.

.. describe:: __image_size

    Size in bytes of the first cover image in the file.

.. describe:: __length

    The length of the file in MM:SS format, or HH:MM:SS from an hour on, e.g. 03:25 or 01:02:05.

.. describe:: __length_seconds

    Length of the file in seconds.

.. describe:: __mode

    One of, Mono, Stereo, Joint-Stereo or Dual Channel.

.. describe:: __modified

    The last time the file was modified in YYYY-MM-DD HH:MM:SS format .

.. describe:: __num_images

    Number of cover images found in the file.

.. describe:: __parent_dir

    The name of the parent directory of the directory the file's contained in. Cannot be written to.

.. describe:: __path

    The absolute filename of a file including directories. e.g /media/Multimedia/Music/myfile.mp3

.. describe:: __size

    The size of the file in bytes.

.. describe:: __tag

    Comma-Separated list of tags found in file. Eg. VorbisComment, ID3v2.4, ID3v1.1

.. describe:: __tag_read

    The tag that'll get written to in the file.

.. describe:: __total

    If the track field is of track/numtracks format, returns numtracks. Can also be written to.


Functions Only
--------------

Only available for Functions is:

.. describe:: __selected

    Having __selected as the field will apply the selected function to the selected cells. So if you have the album field selected in one file and artist in another. The function'll be applied to the album field of the first file and artist of the other respectively.


Cover Art
---------

Cover art can be accessed using the **__image** field. Use it only in Function like :ref:`Remove Fields <remove_fields>` as album cannot be displayed anywhere other than the :ref:`Artwork window <artwork_window>` and :ref:`Extended Tags <extended_tags_menu>` dialog.

* For ID3 tag cover art, writing multiple pictures per file is supported, but a different description is required for each.
* MP4 tags also support multiple pictures per file, but not setting descriptions.
* APEv2 tags can store at most two pictures per file. Moreover, these pictures need to have different cover types, limited to **Cover (front)** and **Cover (back)**.
* VorbisComment tags support multiple pictures per file with no limit on the descriptions or cover types.


Tags
----

The table below lists ID3v2.4 frames, MP4 atoms and WMA attributes with their respective puddletag fields. :doc:`This <id3>` page lists ID3 Frames and the various ways to edit them in puddletag, including what happens to TDAT, TIME, TORY, TRDA and TSIZ, which only ID3v2.3 has.

Any MP4 atoms not in this list will be assumed to be freeform frames, written using ':com.apple.iTunes:**fieldname**' as the atom. ID3 frames not found will be written as TXXX frames of the form **TXXX:fieldname** frame.

MP4 keeps track and disc numbers apart from their totals: **track** and **totaltracks** share the trkn atom, **discnumber** and **totaldiscs** the disk atom, each a whole number; writing **track** as 3/12, or **discnumber** as 1/2, sets both. The flags (cpil, pgap, pcst) read **1** or **0**, as MusicBrainz Picard and Mp3tag show them; **1** or **Yes** turns one on, anything else off. ID3's **itunescompilationflag** (TCMP) saves **Yes** and **No** as **1** and **0** too. MP4 keeps lyrics as plain text, so a language and description in front, as ID3 takes them (**eng||Lyrics**, **eng|Description|Lyrics**), aren't saved. tmpo and the iTunes IDs (akID, atID, cmID, cnID, geID, plID, rtng, sfID, stik) take whole numbers.

Some MP4 fields used to have names of their own, and writing those still sets them: **disc** is now **discnumber**, **artistsortorder** is **performersortorder**, **composersortorder** is **itunescomposersortorder**, **partofcompilation** is **itunescompilationflag**, and **lyrics** is **unsyncedlyrics**, as in ID3.

In WMA files, **comment** is the Description attribute, and **unsyncedlyrics** is WM/Lyrics, plain text as in MP4: a language and description in front aren't saved. WM/IsCompilation reads **1** or **0**, as MP4's flags do, and **1** or **Yes** turns it on. Some WMA fields used to have names of their own, and writing those still sets them: **comment:** is now **comment**, **lyrics** is **unsyncedlyrics**, **album_subtitle** is **setsubtitle**, **encodersettings** is **encodingsettings**, **label** is **organization**, **originalfilename** is **filename**, **originallyricist** is **author**, **remixer** is **arranger**, **subtitle** is **version**, and **wwwaudiosource** is **wwwsource**, as in ID3; **engineer** is **producer**, as MusicBrainz Picard calls WM/Producer. Any other field is saved as an attribute of its own name. WMA's own attributes have a / in their name, like WM/Provider: puddletag doesn't show those it has no name for, and keeps them as they are.

VorbisComment (Ogg, FLAC) and APEv2 fields show with the name they have in the file, in lower case (**TITLE** shows as **title**), except these:

* VorbisComment: **tracknumber** shows as **track**, and **date** as **year**.
* APEv2: **disc** shows as **discnumber**, and **album artist** as **albumartist**; they're saved under the file's own key, or as Disc and Album Artist (Mp3tag's AlbumArtist is kept as it is), and writing **disc** or **album artist** still sets them.

Neither format tells keys apart by case, but some players do, so saving keeps each key as the file has it (TITLE stays TITLE, Title stays Title). A new key is saved the way each format's specification writes them: in upper case in VorbisComment (TITLE), and with each word capitalised in APEv2 (Title, Record Date), except the APEv2 keys Debut album, EAN/UPC, ISBN, ISRC and LC.

Some formats limit field names: VorbisComment's are ASCII from space to } and can't contain =; APEv2's are 2 to 255 ASCII characters from space to ~, other than ID3, TAG, OggS and MP+; MP4's freeform ones are Latin-1; WMA's can't contain /. ID3 takes any name. A field whose name its file's format can't take isn't saved: puddletag reports it as it does a file it can't write, and the file keeps its tags.

The MusicBrainz ids the tag sources return are saved where `MusicBrainz Picard <https://picard-docs.musicbrainz.org/en/latest/appendices/tag_mapping.html>`_ saves them, and files tagged by Picard show them under these names. Except in WMA, they're mappings (Preferences, Mappings), so they can be changed there.
